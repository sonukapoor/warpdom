- **`var()` with `!important` in style rules, jsdom 28.1 to 29.1** (#138, #142): in the jsdom 28.1.0 to 29.1.1 profiles, a declaration that uses `var()` in a style rule loses its `!important` in the cascade, as in jsdom (custom properties keep it). For example, `.i { padding: 1px !important } .j { padding: var(--p) !important }` now computes `padding: 1px`.
- **Computed style mutation methods through jsdom 28.0.0** (#142): in the jsdom 28.0.0 profile, `setProperty()`, `removeProperty()` and `cssText` on a `getComputedStyle()` result still work, as in jsdom 28.0.0; from 28.1.0 they throw `NoModificationAllowedError`, as before. Assigning a property (`getComputedStyle(el).width = '10px'`) works in every profile, as in jsdom.
- **Test setup:** warpdom's own parity tests for jsdom 27.1 to 28.1 now run each jsdom release with the cssstyle it uses in a real install, instead of a shared copy (#138). The 28.1.0 version boundaries from 0.1.8 and 0.1.9 were re-checked against clean installs and hold.
- #142 was checked on 19 open-source suites plus Ant Design and Mantine (GitHub Actions, jsdom vs warpdom): no test changed status apart from the known, documented differences.
