- **`element.style` and computed style are `CSSStyleDeclaration` objects with the property accessors on that one prototype** in the jsdom 20-28 profiles, as in jsdom (#72, #94), so `vi.spyOn(CSSStyleDeclaration.prototype, 'width', 'get')` and `jest.spyOn` intercept `el.style` and computed reads and writes. The accessor set and the methods follow the cssstyle version each jsdom release loads (2.3.0 to 6.x). From jsdom 29 the chain stays `CSSStyleProperties` > `CSSStyleDeclaration`. Not modeled (see "Differences from jsdom"): with cssstyle 5.3.7 and earlier, jsdom's `setProperty`, `cssText`, `setAttribute('style')` and `getComputedStyle` also go through a spied setter.
- **Computed values per jsdom version** (#84, #103), measured on every jsdom release from 20.0.0 to 30.1.3 and cssstyle 2.3.0 to 6.2.0:
  - Colors: before 22.1.0 they compute as declared; 22.1 to 26 resolve named, hex and functional colors but keep system colors as declared; from 27 system colors resolve to jsdom's values (all 47 keywords). The cssstyle generation decides keyword case, the known system colors and the color parser; a numeric alpha rounds to 3 decimals.
  - A declared `0` stays `0` before 28.1.0 where cssstyle does not parse the property; `margin`, `padding` and `border-width` keep their declared form before 27; from 29.0.2 an undeclared `font-family` is `depends on user agent` and `vertical-align: inherit` inherits.
  - jsdom 30: a length or math function (`calc()`, `min()`, `max()`, `clamp()`) computes to px, as do font size keywords, `larger`/`smaller` and percentages; `bolder`/`lighter` from 30.1.0.
  - An SVG `a` with `href` matches `:link` and `:any-link`. The default cssstyle per jsdom release is now 2.3 up to 21.0.x, 3.0 from 21.1 to 23.0.x and 4.x from 23.1.0.
- **`<dialog>` user agent styles** per jsdom version (#76): colors through the named-color rule in jsdom 20 to 22.0, `inset-inline-start: 0` in 27.0 to 28.0.
- **A `var()` shorthand and a longhand meet by document order, per jsdom version** (#117, #118): a longhand left pending by a shorthand such as `padding: var(--p)` no longer wins over a later, less specific longhand by specificity. Before jsdom 28 the latest pending and the latest declared longhand meet by order; from 28 to 30.1.2 each one's winner by specificity is chosen first; from 30.1.3 only two `!important` declarations still meet by order. This fixes a regression from #103 in 8 Ant Design `Descriptions` tests.
- **Form and CSS rule interfaces shaped as in each jsdom version** (#70, #71, #116): the form collections, `RadioNodeList` and (from jsdom 26.1.0) `HTMLFormElement` have their own `@@iterator`, iterating live like jsdom's; `autofocus` is on the four form controls and `inputMode` on `input` and `textarea`; before jsdom 27.1.0 the CSSOM classes have the older shape (legacy `CSSRule` constants, `CSSStyleRule` directly under `CSSRule`, `CSSStyleRule.parse()`, own `parentRule`, `parentStyleSheet` and `cssRules` on each rule, the older `cssText` and `conditionText` setters); `CSSSupportsRule.prototype.matches` from jsdom 29. warpdom now has every member the newest jsdom of each major from 20 to 30 has.
- **Window setters and their receiver as in jsdom, per version** (#90, #96): in the 21 to 26 profiles, `Object.create(window).self = 7` gives the derived object its own property and leaves `window.self`; from 27 the `status` and viewport setters act on their own window whatever `this` is, and an assignment through a derived object replaces the window's member. Members made on first read (interface objects, `Image`, `Option`, `Audio`, `console`, `webkitURL`, `HTMLDocument`, `WebSocket`) give a derived object its own data property instead of replacing the window's.
- **XMLHttpRequest follow-ups** (#92, #93): `overrideMimeType()` with a label that names no encoding keeps the response's charset; a document's `characterSet` uses the Encoding standard's names (`ISO-8859-2`, `Shift_JIS`, ...); `open()` converts its arguments first, as jsdom does; stopping a request cancels a pending preflight and a pending body read, so a mocked stream that ignores the abort signal can't stay active; in the jsdom 28+ profiles upload handlers run before the response is stored. `window.atob`/`btoa` and `readAsDataURL` use the platform's `atob`/`btoa`, so the CommonJS bundle works in a VM context without them.
- **Other behavior changes** (each toward jsdom's results): before jsdom 29 there is no `window.CSSStyleProperties`, and style objects have no `@@toStringTag` or `@@iterator`; `CSSStyleProperties.prototype[Symbol.iterator]` is `Array.prototype.values` from 29; computed colors, zeros and box shorthands read differently in the profiles listed above; a document's `characterSet` is in the Encoding standard's case.
