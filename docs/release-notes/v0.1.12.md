- **Callbacks are called directly, as jsdom calls them** (#164, #170): `FormData`, `URLSearchParams` and `Headers` `forEach`, `MutationObserver` callbacks, event listener functions, `on*` handlers (including `window.onerror`'s five arguments) and custom element lifecycle callbacks run even when the function's own `call` or `apply` property has been overwritten, as in every jsdom from 20 to 30. A `TreeWalker` or `NodeIterator` filter function gets an `undefined` `this`, and `FormData.prototype.forEach` throws for a non-callable callback even when there are no entries. `FormData.forEach` walks the live entry list: entries appended or deleted by the callback are visited or skipped as in jsdom.
- **A closed window is no longer kept alive** (#165, #169): the last list read and the cascade's last style root were held by module-level caches, so one closed window (and its DOM) stayed in memory until the next read. They are cleared when a window is closed or reset and when a Vitest or Jest environment is torn down, and the cascade no longer keeps its root between calls.
- **`warpdom compare` on a project already on warpdom** (#172, #178): `--baseline jsdom` (or `happy-dom`) runs the baseline on that DOM and warpdom in the other run, so a migrated project can be checked against jsdom again; the baseline DOM must be installed (compare says how when it isn't). `warpdom migrate` names the DOM the tests actually ran on in its jsdom version notes and pins a jsdom version only for the runner and package whose tests ran on jsdom; its manual step no longer prints an empty "add" list.
- **Switching back to jsdom** (#171): new [docs/switching-back.md](https://github.com/sonukapoor/warpdom/blob/main/docs/switching-back.md), linked from the README: going back for the whole project, one file or one run, running both side by side, undoing `warpdom migrate`, and uninstalling.
- **`resetWindow()` releases discarded iframes' windows** (#173, #176): a reset left the frame windows of removed iframes attached, so `window.length` grew with every reset and their timers stayed alive. They are now destroyed, and `window[0]`, `window[1]` and so on point at the frames that remain.
- **`FormData` iterators walk the live entry list** (#174, #177): `entries()`, `keys()`, `values()` and `[Symbol.iterator]()` see entries appended or deleted during iteration, as in every jsdom from 20 to 30, and the iterator objects have jsdom's shape.
- **The default style sheet cascades by specificity from jsdom 28.1** (#136, #180): in the 28.1 to 30.1.3 profiles, the user agent sheet's rules meet the page's by specificity, as in jsdom, instead of losing to any page rule. For example, `* { display: inline }` leaves a `div` as `block`, and the `hidden` attribute's `display: none` counts as specificity (0,2,1).
- **Fast mode: a file's globals no longer leak into the next file** (#175, #186):
  - The per-file reset removes globals a previous file's tests added, and puts back window members they replaced.
  - A file whose tests are all skipped doesn't make the next reset use a stale mark.
  - A `vi.stubGlobal` or `vi.spyOn` made in a setup file, then undone by Vitest's cleanup or by a test, is no longer brought back.
  - Fast-mode configs run setup files in order (`sequence.setupFiles: 'list'`), so the reset runs before a file's own setup.
  - On Vitest 3.2 the reset doesn't take effect yet (#196).
- **System colors switch with `color-scheme: dark` from jsdom 27** (#51, #188): `Canvas`, `CanvasText`, `ButtonFace` and the other system colors resolve to jsdom's dark values under `color-scheme: dark`. For example, `ButtonFace` is `rgb(51, 51, 51)`. A disconnected element keeps its colors until the document changes, as in jsdom.
- **`warpdom compare --baseline` and `warpdom migrate`: nested projects, existing warpdom tests, custom environments** (#185, #190):
  - `compare --baseline` switches nested external Vitest projects too.
  - `migrate` keeps the jsdom version that tests already on warpdom ran on, whether a config names warpdom by package name, by path or by an imported environment. A config that names its own `jsdom` version keeps it.
  - Each runner in a package keeps its own version.
  - A project's own environment in a directory named `warpdom` no longer counts as warpdom.
- **`background` with an escaped quote, parenthesis or space in `url()`, cssstyle 4.4 to 4.6** (#163, #191):
  - The first time a process meets such a `url()`, the other components of the value apply, and the image the declaration had stays. Afterwards, the whole value is rejected, as jsdom 23.2 to 26.1 with cssstyle 4.4 and later do: cssstyle caches the `url()`.
  - This also applies to `style` attributes from the HTML and XML parsers.
- **`border: none` and `border-style: none` are kept in the jsdom 27.4 to 29.1.1 profiles** (#179, #195):
  - These profiles had dropped them; they now serialize as jsdom does (`border: medium`).
  - A side with a `none` style and CSS-wide keywords on `border` are kept too.
  - From jsdom 29.0.2, an inherited `currentcolor` resolves to the inheriting element's own color.
- **Shadow trees' style sheets and kept computed values, as in jsdom** (#137, #198):
  - Before jsdom 30.1.2, a `<style>` in a shadow root doesn't apply. From 30.1.2, shadow sheets are not scoped: they appear in `document.styleSheets` and apply to the whole document.
  - Document sheets apply inside shadow trees, and shadow children inherit nothing from their host.
  - From jsdom 21 to 30.1.1, an element's computed style is kept from its first read until the document's own tree changes. Rule edits don't refresh it, and from 29, neither do another window's `insertRule()`/`deleteRule()`.
- **Frames: an insertion defines only its own index property** (#184, #206):
  - `window[0]`, `window[1]` and the other index properties were redefined on every iframe insertion. Removing 1,000 iframes now takes 33 ms instead of 77.
  - An iframe inserted (or inserted and removed) while `resetWindow()` runs no longer leaves `window.length` wrong or loses a snapshotted index.
- **Docs** (#197, #194):
  - The README is shorter. Per-version details are now in [docs/jsdom-versions.md](https://github.com/sonukapoor/warpdom/blob/main/docs/jsdom-versions.md), and the full list of differences from jsdom is in [docs/differences.md](https://github.com/sonukapoor/warpdom/blob/main/docs/differences.md).
  - The packages have more npm keywords, and the companion packages have `homepage` and `bugs` links.
