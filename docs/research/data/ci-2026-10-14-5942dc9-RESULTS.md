# Results of the strong baselines and measured isolation at warpdom 5942dc9 (2026-10-14)

The strong-baseline experiments of the 208ad49 re-run (`ci-2026-10-13-208ad49-RESULTS.md`,
section 3), run again with warpdom 5942dc91def7c179e73834961efbdc533f76dea6, which differs from
the frozen commit 208ad49 only in the fast-mode command (`src/vitest-fast-{cli,reporter,state}.js`:
the error-attribution fix 0596184 and up to 4 split runs instead of 2; `git -C ~/Projects/warpdom
diff --stat 208ad49 5942dc9 -- src`). The DOM code is identical, so every drop-in, correctness,
version, ablation and WPT number of the 208ad49 re-run holds for 5942dc9; this file replaces only
its measured-isolation numbers. All numbers are recomputed from the archived raw data in this
directory; each table or statement names its source.

**Sources and how to reproduce.**

- `<dir>/report.md` (dir = `ci-2026-10-14-5942dc9-baselines-{tuning,heldout,apps}`):
  `ablation-report.cjs timing-ci.csv --learning learning.jsonl --pertest <extracted pertest>`,
  dom-api-tracer 4fe9e95 (report scripts unchanged since 843087f; `npm test`, which includes the
  scripts' self-checks, passed first). Each is byte-identical to its CI run's report job.
- `ci-2026-10-14-5942dc9-computed.md` ("computed" below): every derived number the report does
  not print, generated by `tools/results-5942dc9.cjs` from the archive alone (the measured-isolation
  part of `tools/results-208ad49.cjs` with the same helpers, conventions and bootstrap, extended:
  every configuration per suite, A1, per-learning modes, timed-run modes and re-runs, false passes
  per test, P3 against two thresholds, and the comparison with the 208ad49 baselines).
- `ci-2026-10-14-5942dc9-correctness-{warpdom-learned,jsdom-learned,warpdom-default}.tsv`: every
  test whose status differs from the same round's jsdom-default (`tools/correctness-inventory.cjs`).
- `<dir>/g2-candidates.tsv`, `<dir>/differences-by-kind.txt`: `tools/g2-candidates.cjs`,
  `tools/classify-differences.cjs`.

**Conventions** (as the 208ad49 RESULTS). Speedup = median over rounds of time(baseline) /
time(configuration) in the same round, given with the **range** of the per-round ratios.
Cross-suite medians carry a **two-level bootstrap** (suites, then rounds; 10,000 resamples, seed
0x5eed): it captures the choice of suites and the between-round noise within one job, not the
variation between runs or runners. "Tests differing" = the most in any round against that round's
jsdom-default, raw (without the job's flaky tests: those whose status changes between the job's
jsdom-default runs, warm-up included). **Best correct jsdom configuration** = the fastest (median
time) of jsdom-default, -shared, -sharedclean and -vm whose tests match jsdom-default in every
round, the flaky set excluded (ablation-report.cjs); jsdom-learned is not a candidate (author
decision). All 17 suites resolve jsdom >= 20 (version rule; 208ad49 computed,
"Version rule"). Names: the data's "learned" (`warpdom-learned`, `jsdom-learned`) is the accompanying paper's
*measured isolation*; "mode" is the warm-up learning's, which the timed runs use.

## 6 Correctness, false passes (G2) and P3

**Correctness** (`ci-2026-10-14-5942dc9-correctness-warpdom-learned.tsv`). warpdom-learned

"largeStep ... explicit largeStep", 1 of 5 rounds) differs for the drop-in in other 208ad49 jobs.

**6 tests with no result** (all of `app/src/sandbox/combobox-multiple-select/test.ts`, its one

rounds and "min and max fraction digits" 1 of 5, both flaky on jsdom in the 208ad49 job; Toast,
flaky), melt-ui 1 (Popover, flaky) and solid-primitives 25 (flaky).

**False passes** (computed, "False passes"; CSV false_pass column). A false pass: passed under the
learned configuration, not passed in the same DOM's isolated run of the round.

- warpdom-learned, 34: ark-ui 4 (round 1: "largeStep should use an explicit largeStep when Shift
  is held"; rounds 2, 3, 5: "largeStep should increment by the default largeStep"), solid 1
  (round 2, the transition test; solid ran isolated, the suite's own `isolate: false` order),
  solid-primitives 29 (flaky set).
- jsdom-learned, 55: ark-ui 8 (smallStep and Toast, isolated mode: no file shared), melt-ui 1
  (Popover, flaky), solid-primitives 46 (flaky set).
- **One G2 candidate.** ark-ui's "explicit largeStep" test passed under warpdom-learned in round 1,
  in a file that ran shared (react split), while it failed in all 6 warpdom-default runs of this
  job (and in every jsdom run). At 208ad49, with the same DOM code, the drop-in (isolated) passed

  failing in every isolated run. File orders were not shuffled.

## 10 Anomalies

1. **The timed runs use the warm-up learning, not the round's learning.** The run records show
   ark-ui running react split in all 5 timed runs while learnings 2-4 chose all isolated (and, at
   208ad49, CopilotKit fully isolated in every timed run while learnings 1 and 4 chose vue split).
   This is the harness's design (ablation-isolation.sh: "the timed run is a normal `warpdom vitest
   run` on the state from the warm-up learning"); the per-round learnings measure stability and
   cost only. Statements that "each round learns and then runs" are imprecise.
2. **ark-ui's best correct jsdom configuration depends on the flaky set.** jsdom-vm differs from
   jsdom-default only in the NumberInput smallStep/largeStep and Toast tests, which fail in every
   jsdom-default run of this job but change status between jsdom runs in other jobs; the rule
   (flakiness from this job only) excludes jsdom-vm here and included it at 208ad49. Section 3
   gives both medians.
3. **One G2 candidate** (Section 6), most likely a flaky pass.
4. **jsdom-learned lost results on ariakit:** 6 tests of one file had no result in its one round,
   after the emulation re-ran 19 files (2 new leaky). The emulation is the harness's, not the
   command; no warpdom-learned run lost a result.
5. **Emulation and command disagree on emoji-picker-element and CopilotKit:** the emulation on
   jsdom splits emoji-picker-element in every learning (1.08x), the command on warpdom keeps it
   isolated (the split does not beat the isolated run by the margin); on CopilotKit the emulation
   on jsdom splits 1 of 3 learnings, the command splits vue in 3 of 3. Different DOMs and
   timings, so not a direct contradiction; the emulation still does not see unhandled errors.
6. **naive-ui:** the command's split (83.5 s) is slower than jsdom-shared (55.8 s) and
   jsdom-learned (81.8 s), which split with no isolated file; the command isolates 3-7 files
   whose differences come from the reset or from errors now attributed by stack. Not diagnosed
   further.
7. Excalidraw's warpdom-vm produced no results in 3 of 4 runs (as at 208ad49); solid-primitives'
   occasional 22 s run appears in jsdom-default, the drop-in and warpdom-learned.
8. Figures: no figure in [figures/](../figures/) uses these data (Figure S3 is the first CI run of 2026-10-12;
   Figure 1 has no data), so none was regenerated.
